# S3 client

The repository provides a simple S3 client in the `s3/` package for storing and reading objects. It speaks the S3 REST API over plain HTTP and signs every request with AWS Signature Version 4, so it works with Amazon S3 and with compatible services such as Cloudflare R2, Backblaze B2 and MinIO. Only the standard library is used, so the package adds no dependency to the project.

The client covers five operations: put, get, head, list and delete. It is not a full S3 SDK: every object travels in a single request, so multipart upload and server-side copy are not available. Put takes the object as a byte slice, so the object must fit in memory.

When an operation fails, the client returns a `*ResponseError` carrying the HTTP status and, when the service sends an error body, the S3 error code and message. `HeadObject` is the exception: a HEAD response has no body, so its errors carry only the status.

The client is based on PocketBase's internal S3 client. The porting notes below describe what changed.

## Configuration

Configuration lives under `[s3]` in [config/s3.go](../config/s3.go). The framework hosts the shape; the program that talks to the bucket reads it. An empty `endpoint` leaves the section off and the other keys are ignored. When `endpoint` is set, `region`, `bucket`, `access_key` and `secret_key` are required.

| Setting | Type | Default | Description |
|---|---|---|---|
| `endpoint` | string | `""` (section off) | Storage URL with the scheme, for example `https://s3.example.com`. Empty deactivates the section. |
| `region` | string | `""` | Provider region, for example `us-east-1` or `auto` for Cloudflare R2. |
| `bucket` | string | `""` | Bucket that holds the objects. |
| `access_key` | string | `""` | Access key. Store it with `ripc set`. |
| `secret_key` | string | `""` | Secret key. Store it with `ripc set`. |
| `use_path_style` | bool | `false` | Put the bucket in the URL path instead of the host name. Set it to true for Cloudflare R2 and MinIO. |

Set the keys with `ripc`:

```bash
ripc set s3.endpoint https://s3.example.com
ripc set s3.region us-east-1
ripc set s3.bucket my-bucket
ripc set s3.access_key @/path/to/access-key.txt
ripc set s3.secret_key @/path/to/secret-key.txt
```

## Porting notes

The package is based on PocketBase's internal S3 client (`tools/filesystem/internal/s3blob/s3`, release `v0.40.4`, commit `5cec579da984436a258602a46a96302fbd31f77c`). The files were copied verbatim; the only changes are the restinpieces conventions and the put operation, which PocketBase keeps inside its multipart uploader. PocketBase is MIT licensed and its copyright notice is kept in the header of `s3.go`.

| File | Change | Why |
|---|---|---|
| `s3.go` | package doc rewritten | the copied text describes PocketBase features this package does not have |
| `s3.go` | `URL()` no longer uses if-init statements | restinpieces style |
| `s3.go` | `SignAndSend` closes the error response body explicitly and joins the close error only when it is non-nil | restinpieces style; a normal error response still returns `*ResponseError` |
| `list_objects.go` | body close joined with `errors.Join` through a named return | restinpieces style for deferred closes |
| `head_object.go` | body close joined with `errors.Join` through a named return | restinpieces style for deferred closes |
| `delete_object.go` | body close joined with `errors.Join` through a named return | restinpieces style for deferred closes |
| `put_object.go` | new | PocketBase's put lives inside its multipart uploader; the client needs only the single-request upload |
| `get_object.go`, `error.go` | copied unchanged | — |
| `copy_object.go` | not copied | the backup chain never copies objects server-side |
| `uploader.go` | not copied | multipart upload machinery, not needed |
| `s3blob.go`, `blob/`, `filesystem.go` | not copied | PocketBase storage layers built on top of the client |
| PocketBase tests | not copied | the package has its own tests |
